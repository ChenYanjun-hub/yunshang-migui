### 1. 主线闭环：archive → AI 的 e2e 验收

**anchor 史料置顶（route.ts 端）**
- `/api/ai/chat` 现接收额外 body 字段 `from`，匹配 `archive:<uuid>` 时提取 anchor id
- 三段式置顶逻辑：
  1. anchor 已在 RAG 自然命中里 → 移到 hits[0]

- mount 后 `useEffect` 检测到 `initialQuery` 非空 → 自动 `sendMessage({ text })`，**用户不用再点"发问"**
- React strict mode 双跑用 `autoSubmittedRef.current` 守卫一次
- `useState(willAutoSubmit ? '' : initialQuery)` 避免 textarea 闪现预填文本

## 四、踩坑与笔记

1. **AI SDK v6 transport extra body 是 `Resolvable<object>`**。`Resolvable<T> = MaybePromiseLike<T> | (() => MaybePromiseLike<T>)`，所以可以传函数（动态读取 state）。本次 `from` 是 URL 参数固定不变，直接传对象 + `useMemo([from])` 重建 transport 已够。
2. **`sendMessage` 也接受 per-call body**：`sendMessage(msg, { body: { ... } })`。两种位置（transport 全局 vs 每次调用）按需选。
3. **auto-submit 必须 ref 守卫**。React 18+ 严格模式 dev 环境下 useEffect 跑两次，没守卫就会发两条相同消息。生产模式下不会，但开发体验依然要照顾。
4. **dashscope batch 上限是 10**（昨日已记），`embedBatch` 内部按 10 条自动切分，今天 12 条无感跑通；唯一的瑕疵是 `embed.ts` 顶部注释还写着"单次最多 25 条"——下次顺手改掉。
5. **react-markdown v10 自定义 components 时，children 可能是 string、ReactElement、或两者数组**。我用 `Children.map` + `typeof child === 'string'` 判断，但只递归一层就够（因为 `<strong>`/`<em>`/`<li>`/`<p>` 等都通过 components 注入了我自己的渲染器，会再调一次 `withChips`）。
6. **chip 渲染要 `align-baseline` + `inline-flex`**。inline-block 会让朱砂方块影响行高、导致段落抖动；inline-flex + align-baseline 可以让方块"贴在汉字 baseline 上"，行高纹丝不动。
7. **流式 `[1]` 半成品**：模型分块输出 "...句末[" → "1]" 时，第一帧渲染 `[`、第二帧才变 chip。实测 DeepSeek 通常一次性吐出 `[1]` 整体，几乎看不到抖动。如果换模型或弱网络下出现明显抖动，可在 splitChips 里把"末尾未闭合的 `[`"暂时藏起来——但今晚没必要做。
8. **picsum.photos 占位图 + grayscale**：`https://picsum.photos/seed/<seed>/800/<height>?grayscale` 配 sepia 0.18 contrast 0.96 滤镜，能产生不错的"老照片质感"。seed 用 `yunshang-bNN` 命名，与首批 `yunshang-aNN` 区分批次。
