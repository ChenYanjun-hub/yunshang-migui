## 四、踩坑与笔记

1. **单值 padding 解决不了"非对称覆盖层"问题**。Cloud Tour 站点 01（昆明北）位于 NW 角，padding=8 时被 nav 遮、padding=14 时被标题块"CLOUD TOUR · 云游导览"遮。两次失败后才意识到：覆盖层本身是非对称的（nav 在顶部、L1/L2/L3 在右上、station card 在左下），padding 自然也得非对称。**经验**：以后做覆盖层 + 内容布局时，padding API 默认就该是 PaddingBox 形式，不是为了灵活性，是为了对应真实世界。

2. **GSAP pin scroll 是设计师自嗨，对评委是负担**。第一版 Exhibition 用 GSAP ScrollTrigger pin 做"走进展厅"沉浸感，写完用户立刻说"垂直/横向冲突"——pin 的本质就是"劫持垂直滚动转横向动画"，对"想快速浏览"的人极其反人类。**返工**：砍 GSAP，改 `overflow-x-auto + scroll-snap-type: x mandatory`，垂直归页面、横向归画卷，各管各。**领悟**：项目核心叙事是"档案 / 史料 / 长卷"，A 方案的"画卷展开"动作契合；pin scroll 的"沉浸感"是 SaaS landing page 的语言，跟米轨气质有冲突。**记录给未来的自己**：动手前问一句"这个交互的核心比喻是什么"——比喻对了，技术选择就清楚了。

3. **Next.js 16 server component 数据同步：默认 dynamic，但 revalidatePath 是必需的安全带**。Exhibition 是 server component，每次请求查 DB——理论上 admin 改 archive 后立即同步。但 Next.js 16 在浏览器后退 / 上线后 CDN 介入时会拿"短暂旧内容"。**规则**：任何 server action 写数据，都要 revalidate 它能影响到的所有读路径。Cross-module 影响（archives 改了影响 exhibition）特别容易漏。**今晚漏了 4 处** —— /admin/archives/actions.ts 的 create/update/delete/setStatus 全没 revalidate /exhibition。

4. **UGC 不要进 archives 表**。一开始考虑过用 `archives.category = 'ugc_photo'` 复用表，但会污染 archives_embeddings 的 RAG 向量索引（即使 status 隔离，每次嵌入流水仍要扫到）。最终新建 `gallery_photos` 表。**额外代价**：admin 多一个 sidebar 入口、Exhibition 多一个 query。**收益**：RAG 检索完全干净，schema 后续加 `likes / comments / author_id` 也不影响 archive。**结论**：表的边界 ≈ 业务概念的边界，能分就分。

5. **ImageUpload 的 unique URL 命名是隐形保障**。`${Date.now()}-${Math.random().toString(36).slice(2, 8)}.${ext}` —— 每次重新上传都是新 URL，浏览器 / CDN 不会拿旧图替你显示。这种"看起来多余实际很关键"的小设计要保留，不要被"代码洁癖"重构掉。

6. **Decision Note 是项目节奏的隐形支架**。今晚 3 次 Decision Note（Cloud Tour 地图栈 / Exhibition 3D 路线 / UGC 真假上传）—— 每次都是先写、再让用户拍板、再开干。**好处**：写的时候逼自己把 PM 视角和工程视角分开；用户拍板时是"在 3 个明确选项里选"，而不是"在我的描述里揣摩"；开干后没有"是不是该换路线"的第二猜想。**纳入流程**：以后任何超过 1.5h 的功能，先写 Decision Note。

7. **Safari Web Inspector 的网络限速跟 Chrome 不同位置**。在 Safari 顶部菜单栏 → 开发 → 限制网络 → 选 100% 数据丢失。但实测在某些版本对 fetch 不稳定，最可靠是直接停 dev server。

## 七、自我评估

**今晚最大的胜利**：**节奏控制 + Decision Note 模板的成熟**。3 个超过 1.5h 的功能都先写 Decision Note 让用户拍板，没有一次"做了一半发现路线错了"。这种"先选型再开干"的工作节奏比闷头写代码效率高得多——用户拍板花了 5min，避免了至少 2-3h 的返工。**这套节奏正式纳入项目工作流**。

**今晚最有意思的失败**：**Exhibition β 的 GSAP pin scroll 返工**。我自己当时也没意识到 pin 的 UX 债，是用户一个反馈直接戳破。事后想：早期文档（a16z 设计文章 / Smashing Magazine）都警告过 pin scroll 的"被困感"，我接触过这些资料——但写代码时被"GSAP 是教科书技术"的标签蒙了眼，没去问"评委体感是什么"。**经验**：技术成熟度 ≠ UX 适配度。下次评估交互方案时，强制问自己一句"我做的是给设计师看的 demo 还是给真实用户用的产品"。

**今晚最隐蔽的收获**：**revalidatePath 漏洞被用户主动问出来**。如果用户没问"我修改 archive，光影展会同步吗"，这个 bug 至少要拖到 5/22 演示彩排时才会暴露——那时候改是来不及的。**反思**：跨模块的数据同步是"看不见的需求"，server actions 写完不应该立刻 commit，要先列一个"我影响了谁"的清单，逐个 revalidate。**纳入 checklist**：以后写 server action，最后一步必须问"哪些路由读了这张表？我都 revalidate 了吗？"

**今晚的债**：
- Cloud Tour 32 站点真实数据等队友
- Cloud Tour padding `{ top: 30, ... }` 是基于 6 站点摆位调的，到时候要按 32 站点真实分布微调
- Exhibition User Gallery 暂无任何 published 行（migration 跑完后 admin 录入第一批是用户的活）
- AI ErrorBanner 重试/关闭/自动清错三种交互验证
