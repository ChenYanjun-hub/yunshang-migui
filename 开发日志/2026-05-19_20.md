## 踩坑与笔记

### 1. NEXT_REDIRECT 信号在 startTransition 异步包装下会被吞
- 现象：用户输密码 → 按钮转一下 → 停留登录页（不跳）；POST 返回 200 / 303
- 根因：server action 内 `redirect()` 抛出的 `NEXT_REDIRECT` 错误，在 `startTransition(async () => await action())` 这种模式下，React 不能正确把它转换成客户端导航
- 修法：让 server action **只返回结果** (`{ ok, redirect }`)，client 收到 ok 自己 `router.replace` 跳
- 教训：**Server Action 里的 `redirect()` 是一种"信号 throw"**，跟 form action 直接绑定时 React 才能识别；包了一层 client 函数 + `await` 就容易被 transition 吞。**规则**：当 client onSubmit 用 `await action()` 模式时，action 不要 `redirect()`，让 client 控制跳转

### 2. Claude Preview MCP screenshot 在 cream-on-cream 设计语言下基本不可用
- 桌面 1440 通走时，每个页面截图都"看着是空的"
- 实际：MAIN 1440×900 正常 fill，h1 正确居中，字体正确加载
- 原因：JPEG 压缩 + 细衬线字体 + 微对比配色（cream + 接近黑）→ 文字"溶解"在背景里
- 改用 `preview_eval` 读 DOM bounding box + computed font-family 验证布局，比看图准确得多
- 教训：**自动化 UI 验证的工具选择要匹配产品视觉语言**。高对比 SaaS UI 适合截图；editorial / 博物馆类极简 UI 必须走 DOM 探针

### 3. 路由命名一致性：`/map` 不存在，地图在 `/cloud-tour`
- 第一次 navigate `/map` 得 404
- 真实路由是 `/cloud-tour`（导航栏 label "云游导览"）
- 周四 demo 脚本里不能口误说"我们看地图"然后手指打 `/map`
- 这种 url path / nav label / 口语名 三者之间的"语义距离"，多语言（中英双轨）项目特别容易出
- **规则**：以后做演示脚本，URL 写完整不靠记忆
